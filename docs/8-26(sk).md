## 2. 무엇을 고쳤나

### (1) 현장점검 우선순위 — 3중 결함

**CSV의 등급 열이 전 행 "안정"으로 나가고 있었습니다.** 위험 24셀·주의 46셀까지 전부요.
`PolicyPriorityItem`에 `risk_grade`를 안 넘겨서 스키마 기본값이 그대로 실렸습니다.
폐업건수 열은 전 행 0, 상권유형 열은 전 행 빈칸이었습니다.

**화면의 폐업률이 단일 분기였습니다.** 라벨은 "최근 1년"인데요.
`alerts.py`와 `analysis.py`는 이미 누적으로 고쳐져 있었고 이 라우터만 남아 있었습니다.
위험 24셀 중 **19셀이 화성시 평균(5.9%)보다 낮은 숫자로** 표시되고 있었습니다.

**사분면 문구가 실제 규칙과 달랐습니다.** x축은 중위값이 아니라 등급(상위 10%)인데
화면은 "중위값 아래"라고 안내해서, 주의 등급 46셀이 안전해 보였습니다.

### (2) NULL이 0.0%로 둔갑

`(value or 0.0) * 100` 때문에 값이 없는 구간이 "폐업 0%"로 그려졌습니다.
**전체 35,505행 중 7,466행(21%)** 이 해당합니다.

모든 셀의 추이 차트가 0%에서 시작해 4분기째 급등하는 모양이었습니다.
누적값은 4분기가 쌓여야 나오므로 앞 구간은 원래 값이 없는 게 맞습니다.

→ `backend/services/risk.py`에 공용 `pct()`를 두고 NULL을 보존합니다.
차트 아래에 "0%가 아니라 미산출입니다"를 명시합니다.

### (3) 분모 불일치

셀 상세가 `16.04%` 아래에 `"47곳 닫힘 / 전체 53곳"`(89%)을 병기하고 있었습니다.
누적 폐업률의 분모는 **4개 분기 직전점포수의 합**(293)이지 현재 점포수(53)가 아닙니다.
표본충분 231셀 전부 해당했고 배율 중위 4.14배였습니다.

→ `최근 4분기 연 293곳 중 47곳 닫힘 · 현재 점포 53곳`

### (4) 커버율 0%인 동이 초록(안정)

분모가 0이라 비율이 0.0으로 저장됐고, 그 0.0이 "안정"으로 칠해졌습니다.
**판단 불가가 안전으로 읽히고 있었습니다.** (기배동 0/54, 매송면 0/48)

### (5) 동 등급의 분모가 3~6셀

29개 동 중 19개가 표본충분 셀 10개 미만입니다.
지도에서 **가장 빨간 두 동이 동탄8동 2/3(66.7%), 새솔동 4/6(66.7%)** 이었습니다.
셀 단위는 Wilson 하한으로 보정했는데 동 단위엔 같은 방어가 없었습니다.

→ **표본충분 5개 미만 = 판단보류(회색), 5~9개 = 등급은 내되 흐리게.**
색은 등급, 진하기는 근거의 두께입니다. 숨기지 않고 알려주는 쪽을 택했습니다.

### (6) 무인증으로 예측값이 나가고 있었습니다

`/api/analysis/*` 5개 엔드포인트만 인증 가드가 없었습니다.
그중 `/score`가 `grade`, `predicted_rank`, `top_percent`를 반환합니다 —
`public.py`가 "예측값 계열은 어떤 형태로도 내지 않는다"고 못박은 항목입니다.

프론트가 이 엔드포인트를 안 불러서 화면 증상은 없었습니다.

## 3. 코드를 만지는 사람 — Breaking Change

### API 응답 변경

```
GET /api/alerts/vacancy-risk/map
  risk_ratio        float → float | null      판단보류 동은 null
  risk_level        "판단보류" 값이 추가됨
  evidence_thin     신규 bool                 표본충분 5~9개면 true
  hold_notice       신규 str | null           보류 사유 또는 근거 얕음 안내

GET /api/cells/{a}/{i}
  cumulative_denominator    신규 int | null   누적 폐업률의 실제 분모
  denominator_estimated     신규 bool         복원 실패해 근사했는지

GET /api/policy/inspection-priority
  risk_grade / cell_type / cumulative_closure_count 가 이제 실제로 채워짐
  actual_closure_rate_pct 가 단일 분기 → 4분기 누적으로 (값이 커집니다)

GET /api/analysis/*
  인증 필요. 토큰 없이 부르면 401/403
```

### 지도 색이 바뀌었습니다

백엔드가 내리던 색과 `index.css` 팔레트가 서로 달라서, 폴리곤 색과 범례 점 색이
한 화면에서 어긋나 있었습니다. 백엔드를 `index.css` 값에 맞췄습니다.

```
위험  #D51B4C → #ba1a1a   (--error)
주의  #F59E0B → #dd5b00   (--accent-orange)
안정  #10B981 → #1aae39   (--accent-green)
```

### `_pct` 사본을 더 만들지 마세요

`backend/services/risk.py`의 `pct()`를 import해서 쓰세요.
라우터마다 사본을 두면 한쪽만 고쳐졌을 때 화면끼리 다른 숫자를 보여줍니다.

**아직 `alerts.py` / `compare.py` / `public.py`에 옛 사본이 남아 있습니다.**
그래서 지금도 같은 셀이 상세에서는 "—", 비교에서는 "0.00%"로 뜹니다. (아래 4절 참조)

## 4. 문구 원칙 — 새로 생긴 것

### 분모가 다른 두 수를 슬래시로 묶지 마세요

```
쓰지 말 것   47곳 닫힘 / 전체 53곳
쓸 것        최근 4분기 연 293곳 중 47곳 닫힘 · 현재 점포 53곳
             또는   최근 1년 47곳 닫힘 · 현재 점포 53곳
```

눈으로 나눈 값이 큰 숫자와 4배쯤 어긋납니다.

**`BrowsePage.jsx`에 아직 이 패턴이 남아 있습니다.** 공개 화면이라 우선순위가 높습니다.

### "판단보류"는 "안전"이 아닙니다

```
쓰지 말 것   데이터 없음
쓸 것        판단보류 — 표본이 충분한 업종이 5개 미만이라 등급 판정을 보류했습니다.
             위험하지 않다는 뜻이 아니라 판단할 근거가 부족하다는 뜻입니다.
```
