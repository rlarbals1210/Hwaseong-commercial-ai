## 1. 개업률 데이터 결함 보정 (신규)

### 문제

`final_dataset.csv`의 개업률이 분기마다 비정상적으로 튀었다.

```
2024Q3    101곳
2024Q4  9,090곳    ← 90배
```

원인은 제공처의 일괄 재동기화이며, **폐업 쪽 갭필링으로는 원리상 교정 불가능하다.**
갭필링은 `0 < gap <= threshold` 조건으로 "사라졌다 **다시** 나타난" 구간만 메우는데,
개업은 처음 등장한 시점이 문제라 메울 앞쪽 기록이 없다.
`build_dataset.py:99` 주석에도 잔여 스파이크(4106→2491→1443)가 이미 기록돼 있었다.

### 보정 방식

첫 등장 분기 대신 **인허가를 받은 분기**를 개업 시점으로 재배정한다.

| 대상 | 처리 |
|---|---|
| 인허가 매칭 82.7% | 첫 등장 이전의 가장 최근 인허가 분기로 재배정 |
| 인허가가 관측 창(2020Q4) 이전 | 늦게 수록된 기존 점포이므로 개업에서 제외 |
| 미매칭 17.3% | 원본 첫 등장 분기 유지 — **추정을 넣지 않는다** |

기존 `build_age_lookup()`이 주소별 **최초** 인허가만 취해 업력이 과대 추정되던 문제도
"첫 등장 이전의 가장 최근 인허가"로 매칭 규칙을 바꿔 해결했다.

### 결과

```
              변동계수    범위
원본            0.925    0.00 ~ 23.20%
보정            0.500    0.00 ~  8.97%
보정 + ma4      0.170    2.00 ~  5.07%
```

2024Q3의 101건이 1,658건으로 복원되고 2024Q4의 9,090건이 3,017건으로 축소되어
**두 분기가 서로를 메우는 형태**로 정상화됐다.

### 산출물

```
ai/fix_opening_rate.py                신규. 멱등성 있음(md5 확인). 20~40초
data/processed/final_dataset.csv      컬럼 4개 추가 (8 → 12개)
```

추가 컬럼: `개업_율_보정` · `개업_보정_매칭률` · `개업_율_보정_ma4` · `폐업_률_ma4`.
**기존 컬럼은 하나도 변경하지 않았다.** `개업_율_평균`은 보정 전후 비교 근거로 보존한다.

### 파이프라인 순서 변경 ★

```bash
python ai/build_dataset.py
python ai/fix_opening_rate.py      # ← 새로 추가. 빠뜨리면 컬럼 4개 소실
python ai/train_model.py
...
```

`build_dataset.py`가 `final_dataset.csv`를 통째로 새로 쓰므로 **두 명령은 한 쌍이다.**

## 2. 셀 모델에서 `임대료_매핑그룹` 제거

`docs/modeling.md` 2-5절이 이 계열을 "실질 3개 값(동탄권/병점권/경기광역)뿐이라
25개 행정동이 전부 같은 값을 공유하는 시간 대리변수"로 경고했으나, 셀 모델에는 남아 있었다.
feature 중요도도 1.1%로 사실상 쓰이지 않았다.

### 성능 영향 — 사실상 동등

```
스피어만   0.4193 → 0.4184   (-0.0009)
리프트     1.444  → 1.433    (-0.011)
```

**제거 근거는 성능이 아니라 방어 가능성이다.** 문서와 코드의 불일치를 없앤 것이 요지다.
(테스트 구간 3개 평균으로는 0.4992 → 0.5016 / 1.486 → 1.522x로 개선되나,
측정 조건이 달라 `train_model.py` 기본 분할로는 재현되지 않는다. 5절 주의사항 참조)

### 변경 파일 — 둘이 반드시 함께

```
ai/train_model.py          CELL_CAT = ["행정동명", "상권업종중분류명"]
ai/build_explanations.py   CATEGORICAL_FEATURES 동일하게 맞춤
```

`build_explanations.py`는 모델 feature 목록과 대조해 없으면 예외를 던지므로
한쪽만 고치면 파이프라인이 멈춘다.

### 재학습·재적재 완료

```
셀 모델      스피어만 0.4184 / 리프트 1.433x / test_n 1,565
DB 적재      상권셀 35,513 / 예측 1,810 / 순위보유 231 / 기여도 693 / 동요약 29
             표본기준 50 / 유령행 0 / M1 통과
```

`팀원-DB-셋업.md` 기준값과 완전히 일치.

### 미정리 — 점포 모델

`model_store_results.json` 기준 **점포 모델에는 `임대료_매핑그룹`이 아직 남아 있다.**
셀 모델만 검증했으므로 지금은 그대로 둔다. "왜 한쪽만 뺐나"는 질문이 나올 수 있다.

## 3. `import_normalized_db.py` 버그 수정

### 증상

`_supplement_score_only_cells()`가 `fix_opening_rate.py`가 추가한 컬럼 4개를 몰라 `KeyError`로 중단.

### 원인

직전 분기가 없어 트레일링 비율을 못 구한 최신 예측 셀을 점포수만 살려 끼워 넣을 때,
채울 컬럼을 **하드코딩**하고 있었다.

### 수정

컬럼명을 나열하지 않고 `commercial`의 스키마에서 자동으로 도출하도록 바꿨다.

```python
additions = missing.assign(기준_년분기_코드=latest)
for column in commercial.columns:
    if column not in additions.columns:
        additions[column] = np.nan
```

앞으로 `final_dataset.csv`에 컬럼을 더 추가해도 같은 자리가 다시 터지지 않는다.

## 5. 방법론 전면 점검 — 심각한 문제 4건 (진단만, 미조치)

전부 실데이터로 검증했다. **뿌리가 하나다: 한 분기 스냅샷을 그대로 지표로 쓰고 있다.**

| # | 문제 | 확인된 수치 |
|---|---|---|
| 1 | **분기마다 우선순위가 거의 다 바뀐다** | 순위 상관 +0.296, Top10 유지 **1.0개/10** |
| 2 | **등급 기준선이 분기마다 3배 요동** | 위험 기준 6.00% ~ 18.76% |
| 3 | **2025년 폐업 급증이 진짜인지 판정 불가** | 이탈 10,403건, 평시(5,632)의 **1.85배** |
| 4 | **행정동 2곳이 도구에서 안 보인다** | 기배동·매송면 커버율 **0.0%** |

부수 확인 사항:

- 업종 41개(점포 5,893곳, 전체의 13.3%)가 어느 동에서도 표본 기준을 못 넘어 전면 제외
- 조기경보 상위 8개가 전부 점포 54~84개짜리 소표본 셀

### 해결책 — 검증 완료, 미적용

**모든 지표를 4분기 누적으로 전환하면 1·2·3·6이 동시에 완화된다.**

```
              순위 상관    Top10 유지
단일 분기      +0.296      1.0개/10
4분기 누적     +0.857      5.4개/10
```

여기에 신뢰하한(Wilson)을 얹으면 소표본 착시가 잡힌다
(겉보기 10%가 점포 50곳이면 4.35%, 1000곳이면 8.29%로 자동 보정).

### "조기경보"의 의미가 바뀐다

"빠른 신호가 미래를 더 잘 맞힌다"는 통념을 검증했더니 **반대**였다.

```
과거 1분기로 예측    +0.319
과거 4분기로 예측    +0.345
과거 8분기로 예측    +0.501
```

그리고 급변은 대부분 평균으로 되돌아온다(급등 셀 3.0% → 9.7% → **5.5%**).
"최근 변화"의 미래 설명력은 사실상 0이다(p=0.11, R² 증가 +0.001).

> 이 데이터에서 폐업은 **급성 질환이 아니라 만성 질환**이다.
> 조기경보는 "갑자기 나빠지는 곳"이 아니라 "만성적으로 위험한데 아무도 모르는 곳"을 알려주는 것이다.

### 문제 없음으로 확인된 것

| 검사 항목 | 결과 |
|---|---|
| 신설 행정동의 과거 데이터 부재 | 문제 없음. 전부 2021Q1부터 20개 분기 완비 |
| 정상 분기의 폐업 판정 우측 절단 | 문제 없음. 재등장률 0.0~0.5% |
| 개업률 보정이 유형 분류·모델 수치를 바꾸는지 | 문제 없음. 개업률은 모델 feature가 아니다 |

## 6. 모델 성능 개선 실험 — 후보 17종 전부 기각

`store_train_table.csv`·유동인구·대규모점포에서 feature 후보 17종을 만들어 검증했다.
**채택 0개, 제거 1개**(임대료_매핑그룹).

기각된 것 일부: 과거 폐업률 명시 추가, 개업률, 업력 3년미만 비율, 업력 중앙값·표준편차,
상권반경, 소분류 수·다양성·집중도, 유동인구 share(코드 매핑 100% 성공), 업종 포화도·경쟁강도,
인허가 매칭률, 점포수 가중치, 포아송 목적함수, 타깃 4분기 평균.

### 결론이 두 번 뒤집혔다 — 기록해두는 이유

1. 1차: 개업률 추가 시 **+10.8%** → 테스트 구간 하나에서만 잰 값이었다
2. 2차: 구간 3개로 공정 비교 시 **+8.1%** → 두 모델 모두 학습 행을 3,505 → 1,199로 깎은 결과였다
3. 3차(최종): 전체 데이터로 학습하면 **현행이 이긴다**

개업률 4분기 이동평균은 2022Q2를 경계로 결측이 100% ↔ 0%로 갈린다.
LightGBM이 결측을 한쪽 가지로 몰기 때문에, 이 feature는 사실상 **"2022Q2 이전인가"라는 시점 표시**가 된다.
`docs/modeling.md` 5절이 경고한 시간 대리변수 문제와 같은 구조다.

### 모델의 정보 상한

feature 중요도(제거 전 기준)에서 범주형 둘이 77%를 차지했다.
모델은 사실상 "이 동네 이 업종의 과거 평균"을 학습하고 있고, 17개 후보 중 어느 것도
그 이상의 정보를 주지 못했다. **성능을 더 올리려면 모델이 아니라 새 데이터가 필요하다.**

참고로 모델은 단순 과거 평균 베이스라인을 이긴다(0.4193 vs 0.3794, **+10.5%**).
이 비교표는 "테스트 결과 신뢰성" 지적에 대한 직접적인 답이므로 보고서에 싣는다.

## 보고서·발표에 반영해야 할 것

1. **성능 수치 갱신**: 스피어만 0.4193 → **0.4184**, 리프트 1.444 → **1.433**
2. **모델 feature 4개**로 정정 (임대료_매핑그룹 제외)
3. **"화성시 폐업이 최근 급증한다"를 근거로 쓰지 않는다.**
   2025년 이탈이 평시의 1.85배이나 데이터 결함인지 판정 불가하다.
   대신 **지역 간 격차**를 근거로 쓴다
4. 방법론 절에 추가할 문장:
   > 폐업 방향의 데이터 결함은 갭필링으로, 개업 방향의 결함은 인허가 재배정으로 교정했다.
   > 두 방향은 결함의 구조가 달라 같은 방법으로 처리할 수 없었다.
5. 한계 고지: 인허가 매칭률 82.7%, 주소 단위 매칭의 근사성, 최근 분기 개업률 과소 추정,
   2024Q4 잔여 이상치
