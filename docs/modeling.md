# 화성시 소상공인 폐업예측 — 모델링 전 사전 지형도

## 0. 이 문서의 사용법

이 문서는 **다른 방식으로 모델링을 시도할 동료**를 위한 것입니다. "우리가 이렇게 만들었으니
따라오라"는 문서가 아닙니다. LightGBM을 쓰든 다른 모델을 쓰든, 행정동×업종 단위로 가든 점포
단위로 가든, 상관없습니다 — **어떤 방식을 택하든 이 데이터로 작업하는 이상 반드시 마주칠 사실과
함정**을 미리 알려드리는 게 목적입니다. 이미 검증이 끝난 걸 다시 검증하느라 시간 쓰지 않으셨으면
합니다.

수치는 전부 실제 산출 파일에서 읽은 값이고, 옆에 근거 파일을 표기했습니다. 확인 못 한 건
"확인 필요"로 남겼습니다 — 지어내지 않았습니다.

우리 쪽 최종 코드/산출물 위치: 라벨·feature 생성은 `ai/build_and_train_v3_t11.py`, 최종
결과는 `data/processed/model_v3_t11_results.json`. 과거 실험 이력은 전부 `archive/`에
보존돼 있고 `archive/README.md`에 각 파일 설명이 있습니다.

## 1. 문제 정의와 우리의 선택 (참고용, 강요 아님)

| 선택 | 우리가 한 것 | 대안 |
|---|---|---|
| 예측 대상 | 개별 점포의 폐업 여부(0/1) | 행정동×업종 셀의 폐업률(연속값) 직접 회귀 — 우리도 병행 실험함(6절 참고), 셀 표본이 충분히 크면 오히려 이쪽이 안정적이었음 |
| 예측 시점 | 관측분기 B → B+2분기 폐업 여부(`label_h2`) | B+1(`label_h1`, 우리도 비교군으로 씀), B+1~B+4 중 아무때나(`label_h1to4`, 우리는 시도했으나 테스트 구간 오염으로 폐기 — 8절 참고) |
| 집계 단위 | 행정동 × 상권업종 중분류(74종)/대분류(10종) | 소진공 소분류(248종)까지 내려갈 수도 있으나 셀이 더 희소해짐(5절) |
| 폐업 정의 | 소진공 상가업소 명단에서의 이탈 | 인허가 데이터의 폐업일자 필드를 1차 신호로 쓰는 방법도 가능(우리는 교차검증용으로만 사용, 4절) |
| 모델 | LightGBM(binary/regression) | 제약 없음 |

동료가 다른 선택을 하셔도 됩니다. 다만 아래 3~6절의 사실은 선택과 무관하게 적용됩니다.

## 2. 데이터 카탈로그 + 함정 지도 (가장 중요 — 방식 무관)

### 2-1. 소진공 상가(상권)정보 — 점포 존재 여부의 원천

- 경로: `Hwaseong-commercial-ai-main-dataset/소상공인시장진흥공단_상가(상권)정보_분기별데이터/`
- 21개 분기 스냅샷(2020Q4~2025Q4), 화성시(시군구명='화성시') 필터링 결과 `data/processed/sbiz_hwaseong_all.csv`(817,741행)
- **함정 1 — 압축 구조가 분기마다 다름**: 2020Q4~2022Q4는 zip 안에 폴더+inner zip이 한 겹 더 있고, 2023Q1부터는 zip에 시도별 CSV가 바로 있음. 처리 코드는 `ai/build_sbiz_labels.py`의 `load_quarter()` 참고.
- **함정 2 — 2023Q1 대량 이탈은 데이터 결함**(4절에서 자세히 다룸). 이걸 모르고 그대로 라벨링하면 어떤 모델이든 가짜 폐업 신호를 학습합니다.
- **함정 3 — 2026-02 화성시 구 신설**로 일부 인허가 데이터 주소에 `효행구/만세구/동탄구/병점구`가 새로 붙음. 소진공 주소엔 없어서 그대로 매칭하면 실패율이 치솟음(우리는 인허가 매칭 시도 초기에 이걸 놓쳐서 매칭률이 80.8%에서 0%로 떨어졌던 적이 있습니다). 우리는 `data/raw`의 "법정동코드 전체자료.txt" 파일을 실제로는 쓰지 않았고, 정규식으로 해당 구 이름을 제거하는 방식(`ai/build_and_train_v3_t11.py`의 `norm_addr()`)으로 우회했습니다 — 법정동코드 매핑표를 쓰는 게 더 정교할 수 있습니다(우리는 안 해봄, **확인 필요**).

### 2-2. 인허가 데이터(12종) — 폐업 교차검증·업력·면적의 원천

- 경로: `Hwaseong-commercial-ai-main-dataset/화성시_인허가데이터/` (일반음식점·제과점·즉석판매·휴게음식점·약국·미용업·이용업·세탁업·체력단련장업·노래연습장업·인터넷컴퓨터게임시설제공업·대규모점포)
- 소진공 점포와는 상가업소번호가 아예 다른 체계라 **주소 문자열 매칭**(위 `norm_addr`)으로 연결. 매칭률 약 70.3%(인허가일자 유효값 기준, `ai/train_closure_model_v3.log`) / 80.8%(주소만 매칭 기준, `ai/train_table.log`).
- **함정**: 매칭은 지번주소 완전일치라서, 다세대 상가건물처럼 같은 주소에 여러 업체가 있으면 상호명이 다른 엉뚱한 업체가 매칭될 수 있음(실제 사례를 표로 확인한 적 있음 — 예: "당신은지금치킨이땡긴다" 주소로 "친절한미용실"이 매칭됨). 상호명까지 일치하는 경우만 신뢰도가 높음.

### 2-3. 카드매출(경기데이터드림 `TB25BPTCARDDONGM`)

- 경로: `Hwaseong-commercial-ai-main-dataset/카드매출_행정동데이터/card_sales_hwaseong.csv` → 매핑 결과 `archive/card/card_sales_mapped.csv`
- **함정 1 — 2024-02~2024-12(11개월) 원본 자체가 없음.** 전체 재수집을 두 번 시도(같은 결과, 89,386건/79개월 동일)했고, 서버가 월 지정 파라미터(STD_YM/CRTR_YM 등 5종 시도)를 지원하지 않아 재수집 불가 확인. "제공 측 미보유"로 결론. 이 구간은 **어떤 모델이든 카드매출 관련 feature가 100% 결측**됩니다(`data/processed/train_table.csv` 계열 진단에서 확인).
- **함정 2 — 신·구 업종코드 체계가 섞여 있음.** 구코드(A0~X0 등, 2018-01~2021-12 안정)와 신코드(D01~Y05 등, 2024-01~2025-06 안정) 사이 2022~2023년 구간은 월 단위로 체계가 뒤섞여 있고(`ai/verify_2022q4_2023q1_gap.py` 계열), 두 체계는 **집계 범위 자체가 달라 절대값이 안 이어짐**(예: 종합소매 2021Q4→2024Q1 -69.2%, 자동차 -96.7% — 실제로는 매출이 그렇게 줄지 않았음, `archive/card/card_industry_continuity_check.csv`). `TO` 코드는 업종이 아니라 총계(다른 모든 코드 합과 소수점까지 일치 확인, 전체 매출의 50%를 차지 — `archive/card/card_code_coverage_draft.csv`)라 업종 매핑에서 반드시 제외해야 함.
- **함정 3 — share(비중)는 보존되지만 절대값은 안 됨.** 신·구 코드 매핑 후에도 절대값 연속성 검증 결과 14개 업종 전부 "의심"(위 표), share(구성비) 기준으로만 일부 사용 가능. 카드매출 신·구 코드 83개(신코드 전체) 대응은 사람이 검토한 초안(`archive/card/sbiz_card_industry_map_draft.csv`, `industry_mapping_draft.csv`)이 있으나 **확정 아님**.
- **결론(우리 실험)**: 카드매출 feature를 넣어도 안 넣어도 **예측 성능이 완전히 동일**했음(동일 행·동일 기간 공정비교, `archive/experiments/model_comparison_results.json`의 `card_ablation_no_card_same_rows` vs `card_ablation_with_card_same_rows` — PR-AUC 0.0737로 소수점까지 일치). 8절에 더 자세히.

### 2-4. 유동인구 — 두 개의 API, 하나는 못 씀

- **깨진 것**: `Hwaseong-commercial-ai-main-dataset/화성시_유동인구/유동인구_화성시_행정동_시간대별.csv`(API `TB25BPTGGPOPSIGDONGTMM`). 직접 확인: 2021-10, TZ01 시간대 기준 24개 행정동 행이 있는데 **유동인구수 값이 24개 전부 15,660.49로 완전히 동일**(고유값 1개). 시간대(TZ01~TZ10)나 TOT 어느 것을 봐도 행정동 구분이 전혀 안 됨 — 이 파일로는 행정동별 분석이 원천적으로 불가능.
- **쓸 수 있는 것**: 같은 폴더의 `floating_pop_hwaseong.csv`(API `TB25BPTPOPDAYDONGM`, 요일별 집계). 행정동별로 값이 실제로 다름을 확인(2025-06 기준 29개 행정동에 29개 고유값). 다만 이것도 **절대값은 2021-12→2022-01 사이 TOT/요일합 비율이 갑자기 0.143→4.4배로 뛰어 단절**(`ai/new_flow_pop_continuity.log`). **share는 보존됨**(행정동 28개 비교, 스피어만 0.922, 평균 |share변화| 2.17%p — 같은 로그).
- 결론: 유동인구도 **share(행정동 비중)로만 쓸 수 있음**, 절대값 금지.

### 2-5. KOSIS 지역통계

- 경로: `Hwaseong-commercial-ai-main-dataset/kosis_data/`(사업체수·종사자수, 세대·등록인구), `화성시_인구동향_시계열.csv`
- **직접 확인한 결과, 이 파일들은 실제로 읍면동(29개) 단위 값을 갖고 있었습니다**(사업체 파일: 29개 행정동×5개 연도 파싱 확인, `ai/kosis_features.log`). 다만 연도 단위(2019~2023)라 분기 데이터에 결합하려면 2024~2025는 2023년 값을 carry-forward해야 하고(`train_table_v2.csv`의 `사업체통계_carry_forward`/`인구통계_carry_forward` 플래그), **이 carry-forward 플래그 자체가 "2024년 이후 여부"를 그대로 알려주는 시간 대리변수**라 우리는 모델 feature에서 뺐습니다.
- **진짜로 행정동 구분 없이 화성시 전체 값만 있던 건 R-ONE 임대가격지수·공실률**입니다(`Hwaseong-commercial-ai-main-dataset/임대동향 지역별 공실률(공실률)/`, `임대동향 지역별 임대가격지수(시계열)데이터/`). 실제 지역 구분은 "경기(광역)", "병점역", "동탄2신도시", "동탄센트럴파크", "화성남양읍", "화성봉담읍" 정도뿐이라, 우리는 동탄1~9동→동탄권, 병점1·2동/화산동/진안동→병점권, 나머지 전부→경기 광역으로 억지로 매핑했습니다(`ai/build_train_table.py`의 `DONGTAN_GROUP`/`BYEONGJEOM_GROUP`). **이게 사실상 "3개 그룹 식별자"로만 작동해서, 나머지 25개 행정동은 전부 똑같은 값을 공유** — 6절에서 다루는 "시간 대리변수" 문제의 실제 원인이었습니다. 최종 모델에서는 제외했습니다.

## 3. 라벨의 진실 (동료가 반드시 알아야 할 핵심)

폐업을 **"소진공 상가업소 명단에서 사라짐"**으로 정의했습니다. 소진공 데이터가 매출액이 없는
스냅샷 데이터라(다음 분기 존재 여부만 확인 가능) 다른 정의가 마땅치 않았고, 인허가 데이터의
폐업일자는 있지만 갱신이 늦거나 누락되는 경우가 많아 1차 신호로 못 씀(대신 교차검증용으로는 씀).

### 3-1. 2023Q1 대량 이탈은 실제 폐업이 아니라 데이터 결함입니다 (핵심 사실)

2022Q4→2023Q1 사이 소진공 명단에서 **11,223개 점포**가 한꺼번에 사라졌습니다(다른 분기 평균은
1,696개, `ai/verify_2023q1_departure.log`). 이게 진짜 폐업이 아니라는 걸 4중으로 검증했습니다:

1. **통계청(KOSIS) 사업체수 대조**: 소진공은 2022→2023 -16.9%(업종 좁혀도 -13.4%) 급감했는데, 업종범위가 가장 가까운 통계청 도소매+숙박음식업 사업체수는 같은 기간 -5.2%에 그침. 행정동별 증감률끼리도 상관관계가 거의 없음(피어슨 -0.088~0.268, `ai/verify_2022_2023_external.log`).
2. **인허가 교차검증**: 이탈 점포 중 인허가상 "영업/정상" 상태로 남아있는 게 **5,248건(46.8%)**. 폐업확인율은 2023Q1만 36.3%로 다른 분기 평균 48.6%보다 뚜렷이 낮음(`ai/verify_2023q1_departure.log`).
3. **재등장률**: 2023Q1에 사라진 점포 중 **72.1%(8,091/11,223, 상가업소번호 기준)**, 상호명+주소 기준으로는 78.9%가 이후 분기에 다시 등장함.
4. **실물 확인**: 상호명+주소가 정확히 일치하는 사례 10건을 뽑아 인허가 데이터의 영업상태를 확인했더니 전부 "영업/정상"이었음(같은 로그의 표). ※ 지도 등 외부 서비스로 실제 방문 확인까지는 하지 않았습니다 — **확인 필요**로 남겨둡니다(이 부분은 검증 강도가 다른 3가지보다 낮습니다).

**이걸 모르고 원본 라벨(v1: `sbiz_labels.csv`, 1분기 부재=폐업)을 그대로 쓰면, 2022년 폐업률이
9.46%로 다른 해(2~5%대)보다 두 배 가까이 튀는 걸 "실제 경기 악화"로 오독하게 됩니다.** 방식과
무관하게 적용되는 사실입니다.

### 3-2. 우리가 한 보정과 최종 라벨 파일

갭 필링(상가업소번호가 앞뒤로 존재가 확인되는 짧은 부재 구간을 "영업 중"으로 메움) 방식으로
복원했습니다. 갭 길이 분포를 직접 확인했더니 2023Q1 코호트는 기타 코호트와 달리 1·4·7·10분기
(3분기 간격) 다봉분포를 보였고(`ai/build_labels_v3.log`), 이는 화성시 상권 자체가 아니라
**데이터 제공처의 주기적 일괄 재동기화 패턴**으로 추정됩니다. 임계값을 8→11분기로 올려도
2024Q4 스파이크는 그대로였고(원본 13,099건, 임계값8/11 둘 다 9,090건로 불변) 2025Q3는
개선(4,106→2,491→1,443, `ai/build_and_train_v3_t11.log`)됐습니다 — **갭 필링으로 못 고치는
잔여 이상치가 2024Q4에 남아있다는 뜻**입니다.

최종 라벨 파일: `data/processed/sbiz_labels_v3_t11.csv`(임계값11 갭필링 기준), 패널
`data/processed/sbiz_panel_filled_t11.csv`. 갭 필링 로직은 `ai/build_and_train_v3_t11.py`의
`build_filled_panel()`/`build_labels()`. 그대로 쓰든, 원본에서 다시 직접 라벨링하든 동료의
선택입니다 — 다만 **원본을 그대로 쓸 거면 최소한 2022Q4 관측분기(및 이를 참조하는 라벨)는
결함의 영향권**이라는 걸 알고 쓰시길 권합니다.

### 3-3. 근본 한계: 폐업 vs 장기휴업 구분 불가

소진공 스냅샷은 "그 분기에 명단에 있는지"만 알려줄 뿐, 폐업·장기휴업·명의변경·데이터 누락을
구분할 수 없습니다. 갭 필링도 "짧은 부재는 휴업으로 간주해 메운다"는 보정이지, 진짜 폐업 여부를
확정하는 방법은 아닙니다. 인허가 데이터의 영업상태 필드가 더 정확할 수 있으나, 커버리지가
전체 업종을 다 못 잡습니다(12종 한정). 이 한계는 어떤 라벨링 방식을 쓰든 남습니다.

## 4. 우리가 확인한 데이터의 성질 (동료의 방식에도 유효한 사실)

- **셀(행정동×업종중분류) 단위는 표본이 매우 얇습니다.** 36,355개 셀의 점포수 중앙값이
  **7개**(평균 22.49, 최소 1, 최대 615, `ai/panel_skeleton.log`) — 셀 단위로 폐업률을 직접
  집계하면 점포 1~2개 변화로 비율이 크게 흔들립니다. 대분류(10종) 기준은 훨씬 안정적(5,759개
  셀, 중앙값 71개, 평균 141.99 — 같은 로그).
- **폐업 양성비율은 약 5~7%대**로 불균형합니다(최종 모델 Test 구간 6.57%, `model_v3_t11_results.json`).
- **업력이 유효 신호입니다.** 업력만 보는 베이스라인(B1)이 원시 지표(PR-AUC/ROC-AUC) 기준으로
  꽤 강력합니다 — 단, 업력을 "소진공 최초 등장 분기" 기준으로 잡으면 관측 시작점(2020Q4)에서
  좌측절단되어 있어 시간 누수가 섞입니다(6절 참고). 인허가일자로 보정한 실제 업력을 쓰면
  Train/Valid/Test 평균이 39.09/39.93/40.65분기로 균일해집니다(`ai/train_closure_model_v3.log`).
- **상권이 재편 중입니다.** 신흥 개발지(동탄4·6·7·8동, 향남읍, 봉담읍)는 카드매출 share가
  상승(`data/processed/dong_share_shift_ranked.csv`, 동탄7동 +5.02%p 1위)하는데, 이 지역들이
  **폐업률도 같이 높습니다**(share변화↔폐업률변화 피어슨 **+0.598**, `archive/diagnostics/share_vs_closure_check.csv`
  로 재계산 확인) — "share 상승=안정적 성장"이 아니라 "개업·폐업이 동시에 활발한 고회전 지역"이라는
  뜻입니다. 반대로 동탄1동은 share가 가장 많이 떨어졌는데(-4.48%p) 점포수는 오히려 소폭 증가(+1.7%),
  폐업률 변화는 27개 행정동 중 중앙값 수준(같은 파일) — 실제 쇠퇴가 아니라 신흥지에 상대적으로
  밀린 "건강한 희석"으로 보입니다.

## 5. 반드시 피해야 할 함정 (방법론 차원, 방식 무관)

이 항목들은 우리 모델의 실수 목록이 아니라, **이 데이터셋 자체의 구조적 함정**입니다. 다른
알고리즘을 써도 똑같이 마주칩니다.

1. **시간 누수 — 무작위 분할 금지.** 관측분기 B 기준 시간순 분할 필수(우리는 Train ≤2023Q2 /
   Valid 2023Q3~2024Q2 / Test 2024Q3~). year를 feature로 넣지 말 것 — 분기 계절성(Q1~Q4)만 허용.
2. **시간 대리변수.** 행정동 변별력이 거의 없는 feature(위 2-5절의 R-ONE 임대가격지수·공실률처럼
   3개 그룹으로만 갈리는 값)는 사실상 "관측 시점이 언제냐"를 알려주는 자리에 가깝습니다.
   실제로 이걸 포함했을 때(1차 실험) feature importance 최상위를 차지했고, 셀 단위 리프트가
   0.19x(=상위 예측이 오히려 더 안전한 셀)까지 떨어졌습니다. 제거 후 1.85x로 개선
   (`archive/experiments/model_comparison_results.json` vs `model_v2_comparison_results.json`).
3. **업력 좌측절단.** 데이터가 2020Q4부터 시작하므로 "최초 등장 분기 기준 업력"은 초반 관측일수록
   기계적으로 작은 값만 나옵니다(Train 구간 최대 10분기, Test 구간 최대 20분기,
   `ai/train_closure_model_v3.log`) — 이러면 "업력"이 사실상 "몇 번째 관측분기냐"와 동치가 되어
   버립니다. 인허가일자 등 외부 소스로 실제 업력을 보정해야 합니다.
4. **결측이 특정 시기에 몰리는 경우.** 카드매출 관련 feature가 2024-02~2024-12, 2025-07~에
   정확히 100% 결측인데, 이 시기 자체를 모델이 결측 패턴으로 학습해버리면(트리 모델은
   결측을 하나의 분기 조건처럼 씀) 시간 누수와 똑같은 효과를 냅니다.
5. **scale_pos_weight 같은 불균형 보정 기법도 맹신 금지.** 우리는 불균형(양성 5~7%) 때문에
   당연히 넣었는데, 실제로는 이게 early stopping을 1번째 트리에서 멈추게 만들어 **학습을
   통째로 실패**시켰습니다(best_iteration=1, split 62회뿐 — `archive/experiments/model_v2_comparison_results.json`).
   껐더니 best_iteration 111, split 6,882회로 정상화됐습니다. 불균형 처리 기법을 쓸 거면
   반드시 best_iteration/split 횟수를 확인하세요.

## 6. 우리 결과 (비교 기준점으로만)

최종 모델(라벨 v3-t11, `data/processed/model_v3_t11_results.json`), Test 구간 2024Q3~2025Q2,

| 지표 | 모델 | B0(관성) | B1(업력) | 앙상블 |

| PR-AUC | 0.0750 | 0.0668 | 0.0687 | **0.0762** |
| ROC-AUC | 0.5552 | 0.5025 | 0.5207 | 0.5530 |
| Recall@10% | 0.119 | 0.1062 | 0.1017 | 0.1265 |

셀 단위(행정동×업종, n≥30 필터):

| | 스피어만 | 리프트 |
|---|---|---|
| 점포모델 집계(중분류) | 0.293 | 1.145x |
| 점포모델 집계(대분류) | 0.279 | 0.874x |

아닙니다.

**우리 방식의 한계**: 점포 단위 원시 지표(PR-AUC 0.075)는 절대적으로 낮은 편이고, B1(업력)
단독보다 근소하게 나은 정도입니다. 반면 **셀 단위로 직접 회귀하는 쪽이 점포모델을 집계하는 것보다
꾸준히 낫습니다**(위 표) — 개별 점포의 운명보다 "그 동네·그 업종의 전반적 위험도"를 맞추는 게
이 데이터로는 더 현실적인 목표로 보입니다. 대시보드 용도라면 처음부터 셀 단위 회귀로 가는 것도
고려해볼 만합니다.

## 7. 우리가 가본 막다른 길 (동료가 안 가도 되는 길)

| 시도 | 결과 | 동료에게 주는 조언 |
|---|---|---|
| 카드매출 살리기 (재수집·신구코드 매핑·share 변환) | 동일 행·동일 기간 공정비교에서 PR-AUC 0.0737로 **포함 여부와 무관하게 완전히 동일**(`archive/experiments/model_comparison_results.json`) | 시간 대비 효용이 없었습니다. 다만 이건 우리가 쓴 매핑(14개 공통업종, 사람 검토 확신도 "상/중")과 우리 feature 설계 안에서의 결론입니다 — 다른 방식(예: 코드 단위 그대로 임베딩)으로 접근하면 다를 수 있음(**확인 필요**) |

## 확인 필요 목록 (지어내지 않고 남겨둔 것)

1. 법정동코드 전체자료.txt를 이용한 정식 주소 매핑 — 우리는 정규식 우회로 처리했고, 이 파일을 실제로 쓰는 정교한 매핑은 시도하지 않음.
2. 2023Q1 이탈 점포의 "실물(지도 등) 확인" — 상호명+주소 일치 10건의 인허가 영업상태만 확인했고, 외부 지도 서비스로 실제 방문/운영 여부까지 확인하지는 않음.
3. 카드매출을 "포함 여부"가 아니라 다른 방식(코드 단위 원본 그대로 사용, 다른 매핑 규칙 등)으로 살렸을 때도 효용이 없을지 — 우리 실험은 14개 공통업종 매핑 + share 변환 조합 안에서만 검증됨.
4. 인허가 매칭 실패 19.2%/29.7%(관점에 따라 다름, 위 2-2절)의 점포들이 실제로 존재하지 않는 업종(무등록 등)인지, 단순 주소 표기 차이로 인한 매칭 실패인지는 구분하지 않음.
5. 셀 회귀 모델(6절)의 best_iteration·학습 안정성이 표본이 더 커졌을 때(예: 여러 해 누적)도 유지되는지 — 현재 대분류 셀 회귀는 Train 2,233행으로 비교적 작음.
