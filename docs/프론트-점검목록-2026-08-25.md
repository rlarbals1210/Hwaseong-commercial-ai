## 먼저 — 원칙은 잘 지켜지고 있다

고칠 것을 나열하기 전에, 확인된 사실부터.

- **설계 원칙 위반 문구 0건.** "지원 대상 / 우선 지원 / 배분 / 확률" 같은 표현을 전수 검색했는데
  매칭된 6곳이 **전부 부정문**이었다("AI가 지원 대상을 결정하지 않습니다").
- **개별 점포 예측을 암시하는 표현 0건.** 접촉 이력 입력 폼까지 "이 기록은 상권 단위입니다"로
  일관돼 있다.
- **`PolicyPage`의 인라인 등급 고지** — "위험 등급(화성시 상위 10%)"이 오해가 생기는 바로 그
  자리에 있다. 다른 화면이 따라야 할 기준.
- **지도의 판단보류 패널** — "데이터 없음"이 아니라 분모와 사유를 보여준다.
- **`ProvisionalNotice`** — 문구·분기를 전부 서버에서 받는다. 공무원 화면 6개 전부에 붙어 있다.
- **셀 상세의 3영역 분리**(확인된 신호 / AI 기여 요인 / 공무원 확인 필요)와 근거·출처 섹션.

**이 구조들은 건드리지 말 것.** 아래는 전부 그 위에 얹는 마감 작업이다.

## 1군 — 시연에서 질문받는 자리 (6건)

심사위원이 클릭하거나 물어볼 확률 순.

### 1-1. 현장점검 1순위 목록이 막다른 길이다

`backend/schemas.py` `PolicyPriorityItem`에 **`area_id`·`industry_id`가 없다.** 그래서
`PolicyPage.jsx:105-137`의 항목이 `<div>`이고 셀 상세로 갈 수 없다.

라우터는 값을 손에 쥐고 있으면서 안 싣는다(`policy.py`의 `commercial.area_id`).

> "가장 먼저 확인하세요"라고 써 둔 목록을 눌렀는데 아무 일도 안 일어나면
> 도구의 논리 전체가 끊긴다.

**수정**: 스키마 2줄 + 라우터 2줄 + `<Link>` 3줄. **투입 대비 회수가 가장 크다.**

### 1-2. 지도 순위표도 같은 이유로 막다른 길

`MapPage.jsx:72-84`, `schemas.py` `ClosureRateRankingItem`에도 id가 없다.
"폐업률 최악 10곳"을 보여주고 끝난다. 1-1과 같은 패턴으로 처리.

### 1-3. "분석 대상 구역 10개" — 항상 10이다

```js
// DashboardPage.jsx:235
const params = new URLSearchParams({ limit: 10 });
// DashboardPage.jsx:337
<StatCard label="분석 대상 구역" value={data.length} unit="개" />
```

`data.length`는 API limit이라 **영원히 10**이다. 첫 화면 첫 타일에 32px로 뜬다.
실제 표본충분 셀은 231개다.

> "화성시 전체에서 10개만 분석하셨어요?" — 나오기 딱 좋은 질문이고,
> 이 프로젝트의 실제 강점(231셀 + 사각지대 38% 별도 트랙)을 스스로 깎아먹는다.

바로 위 배너 배지는 "예측 상위 10개 구역"으로 정확하다. **타일 라벨 1줄만 고치면 된다.**

같은 문제가 "트렌드 이상 N개"(`:249`)에도 있다 — 상위 10개 안에서만 센 값인데
빨간 톤에 범위 표시가 없다.

### 1-4. 조기경보 1순위 ≠ 현장점검 1순위, 해명이 없다

대시보드에 "현장점검 우선순위 보기" 버튼이 있어(`DashboardPage.jsx:457`)
**시연 동선상 반드시 연달아 보게 된다.** 두 화면의 1등이 다를 확률이 높다.

- 조기경보 = 모델 예측(2분기 뒤)
- 현장점검 = 관측 폐업률 내림차순

답은 이미 준비돼 있는데(`DashboardPage.jsx:305`) **도착지인 현장점검 화면에는 없다.**

**수정**: PolicyPage 헤더에 한 줄 — "이 화면은 관측 기준이라 조기경보(예측 기준)의
상위 순위와 다를 수 있습니다."

### 1-5. 사각지대 → 셀 상세에서 경고가 사라진다

`CellDetailPage.jsx`는 `sample_insufficient`를 **한 번도 쓰지 않는다**(검색 결과 0건).
백엔드는 내려주고 있다.

사각지대 화면은 "폐업률을 판단의 주 근거로 쓰지 마시고 건수를 먼저 보십시오"라고
명시한다. 그런데 링크 한 번 타면 점포 12곳짜리 셀의 16.7%가 **38px로** 뜨고,
그 값이 업종·동·시 평균과 나란히 막대로 그려진다.

> 사각지대는 이 프로젝트가 가장 자랑할 만한 설계다.
> 시연에서 강조할수록 이 자리를 눌러볼 확률이 올라간다.

**수정**: `sample_insufficient`면 대표 숫자를 폐업률 → **건수**로 바꾸고,
비교 막대를 숨기고, 사각지대와 같은 문구의 경고를 올린다. 20줄 내외.

### 1-6. 지도의 "이 동 보기"가 동을 안 넘긴다

```jsx
// MapPage.jsx:387
<Link to="/blindspots">사각지대에서 이 동 보기</Link>
```

`BlindspotPage`는 URL을 읽지 않는다. 도착하면 전체 목록이다.
"조기경보 대시보드에서 보기"도 마찬가지이고, **대시보드에는 행정동 필터가 아예 없다.**

라벨이 "이 동 보기"라 담당자는 필터가 걸린 줄 알고 읽는다. 없으면
"이 동은 문제없구나"로 오독한다.

**수정**: `?dong=` 쿼리 + `useSearchParams`. 대시보드 링크는 라벨을 정직하게 바꾸거나 제거.

## 2군 — 숫자 신뢰도 (4건)

### 2-1. `_pct` 사본 3개가 남아 있다

오늘 `cells.py`만 공용 헬퍼로 바꿨고 나머지는 그대로다.

| 파일 | NULL 처리 | 영향 화면 |
|---|---|---|
| `services/risk.py` `pct()` | **None 유지** | 셀 상세 |
| `alerts.py:58` | **0.0으로 변환** | 조기경보, 지도 순위표, 사각지대 |
| `compare.py:56` | **0.0으로 변환** | 상권 비교 |
| `public.py:81` | **0.0으로 변환** | 공개 탐색 |

**같은 셀이 상세에서는 "—", 비교에서는 "0.00%"로 뜬다.** 0.0%는 "가장 안전한 값"으로
읽힌다 — 지도에서 이미 한 번 겪은 사고와 같은 형태다.

**수정**: 3파일 각 2줄 + 스키마를 `float | None`으로 완화.

### 2-2. 소수 자릿수가 1자리와 2자리로 갈린다

같은 `closure_rate_cum4`가 화면마다 다르게 찍힌다.

| 화면 | 표시 |
|---|---|
| 조기경보 · 현장점검 · 사각지대 · 셀 상세 | `7.1%` |
| **지도 순위표** (`MapPage.jsx:77` raw 렌더) | **`7.14%`** |
| **상권 비교** (`compare.py` decimals=2) | **`7.14%`** |

가장 나쁜 곳은 **공개 탐색 한 카드 안에서 갈리는 것** — 대표 숫자는 1자리(`8.3%`),
바로 아래 비교는 2자리(`5.94%`)라 눈으로 검산하면 어긋나 보인다.

**수정**: 전부 1자리로. 5줄. (신뢰구간처럼 정밀도가 논점인 곳만 예외)

### 2-3. CSV가 화면과 다르고 등급 기준 고지가 없다

- 화면 `7.1%` → CSV `7.14` (가공 없이 raw)
- 화면 "1순위" → CSV `Q1`
- 같은 `store_count`를 한쪽은 "점포수", 다른 쪽은 "영향 점포 수"
- **`GRADE_NOTICE`(위험=상위 10%, 절대 기준 아님)가 파일에 없다**

> 이 CSV는 화면을 떠나 회의자료·의회 답변으로 돌아다닌다.
> 그 시점에 "위험"은 절대 기준처럼 읽힌다.

**수정**: CSV 첫 3줄을 주석행으로(기준 분기 + 등급 고지 + 잠정치 고지), 값은 화면과 같은
포매터를 통과시킨다. 두 화면의 생성기가 거의 동일하므로 `lib/csv.js`로 합칠 것.

### 2-4. 공개 화면에 금지된 슬래시 병기가 남아 있다

```jsx
// BrowsePage.jsx:138
{cell.closure_count}곳 폐업 / 점포 {cell.store_count}곳
```

오늘 조기경보·셀 상세에서 없앤 바로 그 패턴이다. 분모가 다른 두 수를 슬래시로 묶었다.
**로그인 없이 열리는 화면**이라는 점에서 더 나쁘다.

**수정**: `DashboardPage.jsx:135-141` 처리를 그대로 옮긴다. 1줄.

## 3군 — 용어 (4건)

전부 문자열 치환이라 회귀 위험이 없다.

### 3-1. "구역"이 두 개의 다른 단위를 가리킨다

| 화면 | "구역"이 뜻하는 것 |
|---|---|
| 조기경보 · 현장점검 | **셀** (행정동 × 업종) |
| 지도 | **읍면동 폴리곤** |

**"구역이 몇 개입니까" 한 질문에 두 화면이 다른 답을 낸다.**
같은 지도 화면 안에서 "구역"(동)과 "상권"(셀)이 동시에 쓰인다.

**수정**: 셀 = "상권", 폴리곤 = "읍면동". "구역"은 폐기. 8곳.

### 3-2. 행정동 / 읍면동 / 동 혼용

읍면동 7곳, 행정동 3곳, 동 2곳. 둘은 행정체계에서 실제로 다른 개념이고,
**감사·의회 대응을 목표로 내건 도구에서 혼용하면 지적 대상이 된다.**
데이터 출처(GeoJSON `EMD_KOR_NM`)는 읍면동이다.

**수정**: "읍면동"으로 통일. 5~6곳.

### 3-3. 폐업률 이름이 7가지

"최근 1년 폐업률" / "최근 1년 누적 폐업률" / "최근 4분기 누적 폐업률" /
"최근 4분기 누적 관측 폐업률" / "4분기 누적 폐업률" / "실제 폐업률" / "폐업률(참고)"

**현장점검 한 화면 안에서만 세 번 다르게 부른다.** "실제 폐업률"이라는 수식어는
다른 곳의 값도 전부 관측값이라 "저기 있는 건 실제가 아닌가"로 읽힌다.

**수정**: **"최근 1년 누적 폐업률"** 하나로. 상세 설명 문단에서만 "최근 4분기 누적"을 병기.

### 3-4. 빈 값 표기가 6가지

`—` / `0.0%` / "미산출" / "판단보류" / "판단 보류"(띄어쓰기) / "표본부족" /
"해당 없음" / "데이터 없음" / "확인 필요" / "미기록" / `?` / "판정없음"

**수정**: 세 층위로 정리 — ①값이 없다 = `—` ②계산 불가 = "미산출" ③보류 = "판단보류".

## 4군 — 실패 상태 처리 (3건)

### 4-1. 인증 만료를 처리하는 화면이 1개뿐

`MapPage`만 상태 코드를 읽는다.

```js
// MapPage.jsx:38-42
if (status === 401 || status === 403) return "로그인이 만료되었습니다. 다시 로그인해주세요.";
```

나머지 6개 화면은 `apiFetchJson`을 쓰는데 이 래퍼는 상태 코드를 **메시지 문자열 안에만**
담아 던지고, 모든 호출부가 `err`를 버린다.

토큰이 만료되면 `RequireRole`은 localStorage에 토큰이 남아 있어 통과시키고,
화면은 "데이터를 불러오지 못했습니다"만 반복한다.
**담당자가 재로그인해야 한다는 것을 알 방법이 화면에 없다.**

> 시연 중 세션이 끊기면 "데이터가 없는 시스템"으로 보인다.

**수정**: `lib/api.js`에서 `err.status`를 실어 던지고 401/403 공통 처리. 10줄, 전 화면 동시 개선.

### 4-2. 지도가 조용히 실패한다

- 네이버 스크립트 `onerror` 핸들러 없음 → promise 영원히 pending, 흰 사각형
- GeoJSON 실패는 `console.warn`만 → 타일은 뜨는데 폴리곤이 하나도 없음

같은 파일의 `loadErrorMessage`가 API 실패는 아주 잘 처리한다. 그 배려가
스크립트·GeoJSON 경로에만 빠져 있다. **시연에서 네트워크가 흔들리면 바로 드러난다.**

**수정**: 두 실패 모두 `setMapError`로. 5줄.

### 4-3. 로딩 / 0건 / 에러 표시가 제각각

| | 로딩 | 0건 | 실패 |
|---|---|---|---|
| 조기경보 · 현장점검 | 카드형 (문구 다름) | 원인별 분기 (잘 됨) | `--error` |
| 사각지대 · 비교 · 탐색 | 평문 | **없음** | **`--accent-orange`** |
| 셀 상세 | 평문 | 실패와 합쳐짐 | 하위 요청 실패는 무음 |
| 지도 | 순위표만 | 지도 영역 없음 | 기준선 |

- 로딩 문구 4가지, 말줄임표 `…` vs `...`
- **오류 색 `--accent-orange`가 "주의" 등급 색과 같다** — 오류 메시지가 등급색으로 칠해진다
- 로딩 스피너가 안 돈다 (`.spin` 클래스는 정의돼 있고 로그인 화면만 씀)
- 셀 상세의 하위 요청 실패가 무음 → 추이·지원사업·접촉이력 섹션이 통째로 사라짐

**수정**: `components/State.jsx`에 Loading/Empty/Failure 3개. 오류색은 `--error` 고정.

## 5군 — 마감 (4건)

### 5-1. 셀 상세 버튼 4개만 스타일이 없다

"안내문 초안 만들기", "복사", "기록 추가", "저장" — `className` 없음.
`index.css`에 bare `button {}` 규칙이 없어 **OS 기본 회색 버튼**으로 렌더된다.
다른 화면은 전부 `.btn-utility`를 쓴다.

**셀 상세는 시연의 종착지인데 거기만 미완성으로 보인다.** 4줄. 가장 싼 수정.

### 5-2. 등급 배지 5종 중 실제로 칠해지는 건 1종뿐

`index.css`에 `.badge-danger` / `.badge-warn` / `.badge-ok` / `.badge-neutral`이
전부 정의돼 있는데 **뒤의 셋은 어디에서도 쓰이지 않는다.**

- "주의"가 배경 없는 검은 글씨 → 등급으로 보이지 않음
- "안정"이 조기경보에서는 숨겨지고 비교·상세에서는 표시됨
- 상권유형 배지가 화면마다 다른 컴포넌트 (배지 / 20px 제목 / 평문)
- `--accent-orange`가 "주의 등급" + "고회전 유형" + "오류 텍스트" 세 의미로 쓰임

**등급 축은 이 도구의 핵심 산출물인데 5단계 중 1단계만 칠해져 있다.**
필요한 CSS는 이미 있다 — 쓰기만 하면 된다.

**수정**: `components/Badge.jsx` 추출 + 호출부 8곳.

### 5-3. 필터가 URL에 안 남는다

## 순서 제안

```
1군 6건        시연 전 필수.        대략 하루
2군 4건        숫자 신뢰도.         반나절
3군 4건        문자열 치환.         두 시간
5-1, 5-4       싼 마감.             한 시간
────────────────────────────────
4군, 5-2, 5-3  공통 컴포넌트 작업.   여유 있으면
6군            리팩터.              여유 있으면
```

**1군 → 3군 → 2군 순서를 권한다.** 3군(문자열)이 2군(로직)보다 뒤에 오면
용어를 바꾸다 방금 고친 로직을 건드리게 된다.

4군 이하는 8개 화면을 동시에 건드려 회귀 위험이 있으므로 별도 사이클로 두는 편이 안전하다.
