## 1. 시민 직접조회 기능 제거

**삭제**: `backend/routers/consultation.py`, `frontend/src/pages/{ConsultPage,CitizenLoginPage,RoleSelectPage}.jsx`
**수정**: `main.py`(라우터 등록), `schemas.py`(`CitizenLoginRequest`·`ConsultationResponse`),
`routers/auth.py`(시민 로그인), `auth/dependencies.py`(`get_current_citizen`), `App.jsx`(라우팅)

**사유**
1. "읍면동×업종 집계 단위, 개별 점포 노출 없음" 원칙과 개인화 조회가 구조적으로 충돌
2. 위험한 상황의 소상공인일수록 행정 서비스를 스스로 찾아올 여력이 없음
3. 심사기준 "시민 체감효과 20점"의 정의에 **"행정효율 개선"**이 명시돼 있어 배점 손실 없음
4. 제거 전 해당 기능은 사실상 고장 상태였음 — 유동인구 컬럼 부재로 근거 문구가 항상 "0명",
   생존확률이 항상 80~99%로 변별력 0, 경쟁강도 임계값(2/5)이 실제 분포(median 146)와 불일치

**보존**: `backend/utils/business_number.py` + 테스트. "시민 인증 수단을 검토했고 주민등록번호가 아닌
사업자등록번호 형식검증까지 구현한 뒤 의도적으로 제외했다"는 판단 근거로 보고서에 인용하기 위함.

## 3. `growth_prob` → `store_count`

`PolicyPriorityItem.growth_prob: float`에 실제로는 **점포 수**가 들어가고 있었다(AI 성장확률 아님).
소스코드 심사에서 지적당할 명백한 네이밍 오류라 `store_count: int`로 정정하고 타입도 바로잡았다.

수정: `schemas.py`, `routers/policy.py`(내부 변수 `benefit_scale`→`store_count`,
`high_growth`→`high_impact`), `PolicyPage.jsx`(3곳)

## 4. 후속 조치 검토안

| 위치 | 이전 | 이후 |
|---|---|---|
| DashboardPage h3 | AI 정책 제안 | **후속 조치 검토안** |
| (신규) 안내문 | — | AI가 지원 대상을 결정하지 않습니다. 확인 순서를 제안할 뿐이며 최종 판단은 담당자가 합니다. |

| `action_message()` 이상 | 즉시 현장 점검 필요 (트렌드 이상) | 트렌드 이상 — 현장 확인 우선 |
| `action_message()` 표본부족 | 표본 부족 — 참고용, 정책 판단 보류 권장 | 표본 부족 — 통계 판단 보류, **현장 확인 권장** |
| CSV 헤더 | 권고사항 | 후속조치_검토안 |

표본부족 문구는 "아무것도 하지 말라"로 읽히던 것을 "통계 판단은 보류하되 현장 확인은 하라"로 바꿨다.
전체 셀의 78.9%가 표본부족인 상황에서 이쪽이 실용적이고, 사각지대 대응 방향과도 맞는다.

`action_message()` 반환값은 카드 하단과 후속 조치 검토안 섹션 **두 곳에서 재사용**되므로
한 곳만 고쳐도 두 화면이 함께 바뀐다.

## 5. SAMPLE_MIN 30 → 50 (조회 기준만)

### 문제
예측 1순위가 **동탄7동·스포츠 서비스(실제 폐업률 0%)**로 표시됐다. 상위 4개 중 3개가 동탄7동이고
점포 수는 35~36개(경계선). 화면 신뢰도를 직접 훼손하는 상태였다.

### 진단 — 모델 버그는 아님
- 예측순위 산출 로직 정상 (`rank(ascending=False)` → 1위 = 예측 최고)
- 예측 ↔ 실제 스피어만 **+0.4252** (p<0.0001), 예측 하위 10개 실제 평균 0.86%
- 원인: 소표본 경계 셀이 상위권을 점유. `pred_contrib` 확인 결과 기여도 1위가 전부 `행정동명`
  (+7.05 / +5.47 / +6.70 / +4.98 %p) — 모델이 "동탄7동이라서 위험"을 학습

### 민감도 검증 (최신분기 20254 기준)

| 기준 | 셀 수 | 점포 커버 | 상위10 리프트 | 스피어만 |
|---|---|---|---|---|
| 30 | 382 | 74.8% | **1.14x** | +0.4252 |
| 40 | 285 | 67.2% | 2.07x | +0.4747 |
| **50** | **231** | **61.8%** | **1.85x** | **+0.5293** ← 정점 |
| 60 | 184 | 56.0% | 1.79x | +0.5190 |
| 80 | 132 | 47.9% | 1.74x | +0.4983 |
| 100 | 93 | 39.9% | 1.58x | +0.4954 |

### 결정
**조회 기준만 50으로 상향. 학습 필터(`train_model.py CELL_MIN_STORES`)는 30 유지.**
→ 모델 재학습 없음 → 보고서의 스피어만 0.4193 / 리프트 1.444 그대로 유효.

수정: `ai/build_risk_index.py`(단일 진실원천), `ai/import_normalized_db.py`(기본값),
`backend/services/risk.py`(폴백), `backend/models.py`(default), 프론트 안내 문구 3개 파일

### 결과

```
예측 1위  동탄7동·스포츠 서비스 (실제 0.00%)  →  새솔동·한식 (실제 4.17%)
상위 10개 평균 실제 폐업률   3.77%  →  6.27%
분석 업종                    46개   →  33개
```

상위권이 새솔동·동탄9동·동탄1동·정남면·향남읍·팔탄면으로 분산되어 동탄 편중도 해소됐다.
서부권(정남면·향남읍·팔탄면) 진입은 "동탄만 본다"는 지적 방어에도 유리하다.

## 6. 조기경보 배너 교체

개별 1순위 셀 대신 **집단 요약**을 표시한다. 예측은 2분기 뒤를 보는 값이라 개별 셀의 현재
폐업률이 낮을 수 있고, 그 한 건이 배너에 뜨면 모델 전체가 틀린 것처럼 읽힌다.

```
AI 예측 상위 10개 구역 — 2분기 뒤 폐업 위험 상위
이 구역들의 현재 폐업률은 평균 6.3%로 화성시 전체 평균(3.22%)보다 높습니다
※ 예측은 관측 시점 기준 2분기 뒤를 봅니다. 개별 구역의 현재 폐업률이 낮아도 상위 순위에 오를 수 있습니다.
```

마지막 줄이 "0%인데 왜 1순위냐"에 대한 답을 화면이 미리 하도록 만든 장치다.
`CITY_AVG_PCT = 3.22` 상수는 `risk_thresholds.json`의 `avg_closure_rate_pct`와 동일하며,
값이 바뀌면 함께 갱신해야 한다.

### 원인
삭제 범위를 "지금 자격 있는 예측(231개)"으로 한정하고 있었다.

```python
prediction_ids = list(prediction_lookup.values())   # 자격 있는 231개만
session.query(PredictionContribution).filter(
    PredictionContribution.prediction_id.in_(prediction_ids)
).delete(...)
```

SAMPLE_MIN 상향으로 자격을 잃은 셀 151개(382−231)의 기여도 **453행**이 잔존.
"표본 부족이라 통계 판단을 보류한다"고 해놓고 그 셀의 AI 기여 요인은 DB에 남아 있는 모순 상태였다.

### 수정
삭제 범위를 **활성 `model_run`의 모든 예측**으로 확대. `from sqlalchemy import select` 추가.
