## B. NULL을 0.0%로 바꿔 표시 (심각도 높음)

네 라우터가 같은 헬퍼를 각자 갖고 있다.

```python
# cells.py:56 / compare.py:56 / public.py:81 / alerts.py:53
def _pct(value) -> float:
    return round((value or 0.0) * 100, 2)
```

`cumulative.py:98`이 `rolling(4, min_periods=4)`라 **셀의 처음 4분기는 누적값이 NaN**이고
DB에 NULL로 들어간다. `_pct`가 그걸 `0.0`으로 바꾸고, 프론트의
`Number.isFinite(...)` 필터는 `0.0`을 유한값으로 통과시킨다.

**실측**: 전체 35,505행 중 **7,466행(21.0%)** 이 누적 NaN. 셀당 NaN 분기 수는
1,847셀이 4분기 — 사실상 전 셀이다.

증상 두 가지:
1. **모든 셀의 추이 차트가 0%에서 시작해 4분기째 급등하는 모양**이 된다. 실제로는
   "값이 없는 구간"인데 "폐업이 없던 구간"으로 읽힌다.
2. 4분기가 안 쌓인 신규 셀 상세가 "0.0% / 0곳 닫힘 / 신뢰하한 0.0%"로 뜬다.

`public.py`만 `None if cell.sample_insufficient else _pct(...)`로 막고 있다.
**같은 값이 공개 화면에서는 숨겨지고 공무원 화면에서는 0.0%로 노출된다.**

수정: `_pct`를 공용 모듈로 옮기고 `None → None` 반환으로 바꾼다. 한 함수를 고치면
세 라우터에서 동시에 해결된다. 프론트는 "—" 또는 선 끊김으로 처리.

## I. 앙상블 순위가 계산되고 버려짐 (문서 불일치)

두 파일이 서로 다른 말을 한다.

```python
# ai/build_risk_index.py:159-161
# 정렬은 모델 순위와 관측 신뢰하한 순위의 평균(앙상블)이다. 검증에서 리프트가 가장 높았다
# (모델 단독 1.393x / 관측 4분기 1.428x / 앙상블 1.438x).
```
```python
# backend/routers/alerts.py:75-77
# 정렬은 모델 순위(predicted_rank)를 그대로 쓴다. 미래 4분기 폐업률 적중에서 모델이
# 관측 지표보다 낫기 때문이다(스피어만 0.566 vs 0.438).
```

**실제 동작은 후자다.** `risk_index.csv`의 `우선순위`(앙상블) 컬럼은 어디에서도
참조되지 않는다. DB의 `predicted_rank`는 `import_normalized_db.py:187`이
성장확률로 따로 계산한 모델 단독 순위다.

크래시는 아니지만 **발표에서 어느 쪽을 말할지 정해야 한다.** 지금 상태로는
"앙상블로 정렬한다"고 말하면 사실과 다르다.

수정: 앙상블을 쓸 거면 `우선순위`를 DB에 적재하고, 안 쓸 거면
`build_risk_index.py`의 주석과 `우선순위` 컬럼을 제거.
